# NOIOP Pilot Execution Evidence Policy v1.0

Automated harness evidence and institutional pilot evidence are separate evidence classes.

## Harness Evidence

The repository workflow may establish that controlled scenarios execute reproducibly against the public-safe MVP logic, authority constraints, error handling, traceability and disclosure controls.

## Institutional Evidence

Only an authorized institutional pilot can establish real institutional data readiness, organizational usefulness, integration behavior in the approved target environment, institutional acceptance and transaction-specific buyer conclusions.

## Prohibited Claim

A successful automated workflow must not be described as a completed customer pilot, production certification, regulatory approval or institutional acceptance.

## Evidence Integrity

Each generated result contains scenario identifiers and cryptographic hashes for input and result payloads. Workflow artifacts preserve the generated evidence bundle for inspection. A failed scenario causes the automated pilot-validation job to fail.
