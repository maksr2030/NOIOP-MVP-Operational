# NOIOP Pilot Governance & Authority Matrix v1.0

## Authority Principle

NOIOP provides governed intelligence and orchestration support. During the pilot, designated human authorities retain final authority for consequential institutional decisions unless a separately approved policy explicitly defines a narrower automated action.

| Activity | NOIOP | Pilot Operator | Institutional Decision Owner | Security / Governance Reviewer |
| --- | --- | --- | --- | --- |
| Validate submitted pilot data | Assist / flag | Execute | Informed | Review exceptions |
| Generate assessment | Execute | Monitor | Review | Audit |
| Generate prioritization | Execute | Monitor | Review | Audit |
| Produce orchestration recommendation | Execute | Review | Approve / reject | Audit |
| Change pilot policy boundary | No unilateral authority | Propose | Approve | Approve governance impact |
| Release consequential decision | No final authority by default | No final authority | Accountable / final authority | Oversight |
| Override recommendation | Record | Facilitate | Authorized | Audit |
| Handle security incident | Contain within configured controls | Escalate | Informed | Lead / approve response |
| Accept pilot | Evidence only | Recommend | Approve | Concur on control evidence |

## Mandatory Controls

All designated approvals must be attributable. Overrides must preserve reason and timestamp. Authority changes require version-controlled approval. Missing authority evidence blocks acceptance for the affected scenario. Pilot outputs must not be represented as institutional decisions until the required human authority gate is completed.
